## 0. 结论先行（给决策用）

**一句话：小红书小工具是目前国内成本最低的“AI 小产品验证 + 冷启动”渠道，但现在还不是能赚钱的渠道。建议把它当作 App Factory 的“需求验证层和涨粉层”，不要当成 App Store 的替代。**

- **能力**：本质是一个离线 H5 沙箱，挂在笔记下面，点“用一用”就在小红书里打开。纯前端，**不能联网、没有登录和用户身份、没有支付**。平台提供了 15 个原生能力：发笔记、存相册、本地存储/文件、带图评论、窗口信息、单次定位、振动、陀螺仪、**关注作者**，外加一个免费的平台大模型（只能生成文本、非流式、内测要加白名单）。【官方】
- **局限**：zip 包最大 10MB，只能有一个 index.html，兼容基线是 Chrome 61 / ES2017。禁用 fetch、WebSocket、Worker、WASM、eval、iframe、剪贴板、外链跳转、web 定位与 web 传感器（后两者改由平台 API 提供）。存档可能丢。发布门槛据报道是“实名 + 粉丝大于 1000 + 注册满 6 个月”。【官方 + 媒体】
- **技术栈**：标准 HTML/CSS/JS。官方推荐的流程是：复制上传页给的“改写口令”，交给 Codex/Claude Code/Cursor 这类 AI Agent，让它下载官方 Skill（`minitool-zip-builder`）去校验、改写、打包。Taro/uni-app 是给“小红书小程序”用的，跟小工具没关系。没有后端可接。【官方 + 推断】
- **推广**：靠笔记分发。入口有：自己的笔记、别人的笔记（用过的工具别人也能挂）、评论区、搜“小工具”进官方榜单、侧边栏“最近使用”、私信/群/站外分享，以及工具内一键引导关注作者（9.51+）。8 月下旬平台集中推流，加上“合集帖”裂变，带出了单品上百万使用人次的爆款。【媒体 + 从业者】
- **商业化**：小工具本身**没有任何直接变现**（没有支付、没有广告、没有分成），这一点多家媒体都确认过。能走的只有间接路径：涨粉以后接蒲公英商单、带货、知识付费，或者做品牌定制。要真正在站内收钱，得用个体户/企业主体开“交易型小程序”，那是另一套产品。【官方 + 媒体】
- **建议**：**值得做，但要限时、限投入地做。**用 2–4 周、3 个小工具做验证，看三件事：流量、涨粉、用户愿不愿意把结果发成笔记。iOS 那条线保留，用小工具帮它找需求、攒种子用户。如果到 2026 年 Q1 平台还没开放联网或变现能力，就不要在小工具上做重运营的产品。【推断】

## 1. 先把名字理清：小工具 / 小程序 / 小组件 / RED Skill

小红书现在至少有四种“可以挂在笔记上”的东西，很容易混。网上有文章把“小工具”和 RED Skill 说成一回事，这是错的。

| 产品 | 是什么 | 谁能做 | 能否联网 | 能否收钱 | 状态 |
| --- | --- | --- | --- | --- | --- |
| **小工具**（Builder Hub → 小工具） | 离线 H5 沙箱，挂在笔记下面，站内直接打开 | 个人创作者（据报道要实名、粉丝大于 1000、注册满 6 个月） | 否 | 否 | 2026-07 内测，2026-08-18 全量 |
| **RED Skill**（Builder Hub → RED Skill） | 给 AI Agent 用的技能包（口令/文件）。笔记上挂组件，用户复制口令后装到自己的 Agent 里用 | 创作者（需申请“新功能体验”） | 不适用（不在站内运行） | 暂不支持付费 | 2026-06 内测，2026-07 初全量 |
| **小红书小程序** | 类似微信小程序：XHSML + JS，有自己的 IDE、服务端 API、登录、支付 | 企业/个体工商户（交易型需要专业号） | 是 | 交易型可以（目前主要是支付宝） | 早已开放 |

## 2. 能力：小工具能做什么

### 2.1 形态与入口

- **形态**：“运行在受限沙箱里的纯 Web 应用（HTML/CSS/JS），可以当成一个能力受限的浏览器页面”。每个小工具的存储和运行环境互相隔离，彼此不能通信。【官方】[小工具容器能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)（当前线上版本；早期版本页脚写着“最后更新 2026-08-11”，见[CDN 快照](https://fe-video-qc.xhscdn.com/fe-platform-file/104101b8323q4m0uaga06277180ac7t8006ptl0e12ek1g)）
- **怎么挂到笔记上**：在 App 发笔记 → 编辑页底部的“挂件/组件” → 切到“小工具” → 选择 → 发布。读者在笔记里点开就能用，不用跳出 App。【官方】[小工具内测邀请页](https://fe-video-qc.xhscdn.com/fe-platform-file/104101b8322bpulog7u06f48k3g2740000000016rhrpc6)
- **入口文案**：笔记下面是“用一用”。【媒体】[界面新闻](https://www.jiemian.com/article/14822034.html)
- **可以挂别人的工具**：发笔记时，“不仅可以挂载自己做的小工具，也可以挂载别人的你使用过的小工具”。【从业者】[人人都是产品经理 2026-07-20](https://www.woshipm.com/ai/6432615.html)
- **分享和作者主页**：工具可以分享给小红书好友、群组或站外；能看到作者，点了会跳到作者主页。【从业者】同上
- **用户找回入口**：「我」→ 左上角菜单 → 侧边栏的「小工具」→「最近使用」；搜“小工具”能进官方榜单（使用人数榜、7 天活跃度榜、当日新品榜）。【媒体】[什么值得买 2026-09-10](https://post.smzdm.com/p/al3lvmv8/)

### 2.2 能力清单（以官方当前文档为准）

| 类别 | 能做什么 | 说明 |
| --- | --- | --- |
| 渲染 | HTML/CSS/JS、Canvas 2D（完整支持）、WebGL/WebGL2（只能做纯渲染） | 最终代码要符合 Chrome 61 / ES2017 |
| 相机/麦克风 | `getUserMedia({video})` / `({audio})` | 需要用户在系统弹窗里授权 |
| 选图/拍照 | `input type=file` | 不管 accept 怎么设，都只能选图片和视频 |
| 音视频 | 内联播放包里的媒体文件 | 不能加载外部媒体 |
| 发笔记 | `postNote`：带上标题（20 字以内）、正文（1000 字以内）、话题、1–18 张图，或 1 个视频，或 1–18 组实况照片（9.43+） | 回调成功只代表“用户在发布页点了发布”，不代表笔记过审 |
| 存相册 | `saveImageToPhotosAlbum` | 必须由用户点击触发 |
| 临时文件 | `writeTempFile`：base64 转成本地路径 | 只支持 png/jpeg/webp/gif/mp4 |
| 本地缓存 | `setStorage/getStorage/...`（客户端 9.46+） | 单个 key 最大 1MB，总共最大 10MB；可以加密 |
| 文件系统 | `saveFile/writeFile/appendFile/readFile/readDir/...`（9.49+） | 持久目录；卸载或清数据时仍可能丢 |
| 评论区 | `interactionOpenApi`（9.49+）：带着文字和图片草稿打开评论编辑器，还能附带 2KB 以内的“小工具状态快照” | 用户从评论重新打开工具时，可以读到快照、恢复状态；目前只支持图片 |
| **AI** | `window.xhs.AI.createModel(...).generateText(...)` | 平台出模型：`deepseek-v4-flash`（默认）、`dots-3-note-prev`（小红书自研“点点”）。**不需要 API key，也没有 token 费用**。不支持流式；最多 40 条消息、12000 字符；输出最多 2048 tokens；**内测期每个用户每天 100 次**；输入和输出都要过内容审核；**要先按 appId 加白名单** |
| 窗口信息 | `getWindowInfo`（9.49+）：容器尺寸、安全区、顶部返回/我/分享按钮的矩形 | 用来做原生按钮避让，别硬编码状态栏高度 |
| 定位 | `getLocation`（9.49+）：单次定位，可选 wgs84 / gcj02 | 只有单次，没有持续/后台定位；需用户授权 |
| 振动 | `vibrateShort({type})` / `vibrateLong()`（9.50+） | 轻/中/重三档，不能自定义时长和波形 |
| 陀螺仪 | `startGyroscope/stopGyroscope/onGyroscopeChange`（9.50+） | 给的是角速度（rad/s），不是姿态角；无陀螺仪时 errCode 10002 |
| 关注作者 | `followAuthor` / `getFollowStatus`（9.51+）：拉起关注确认，返回 follow_status | **只能关注当前工具的作者，不能指定别人**；同一账号对同一工具每天最多弹 10 次 |
| 弹窗 | `alert/confirm` | 以原生 UI 展示 |

来源：【官方】[小工具容器能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)

**用户逐项问到的能力：**

- **登录/用户身份**：**没有。**能力清单里没有任何登录或用户信息 API，文档还写明“§3.2 列出的即为全部可用 JS API，未列出的能力不受支持”。官方介绍也说，依赖“登录系统、排行榜、云端存档”的作品不适合做成小工具。【官方 + 媒体转述官方】[游戏茶馆/电玩帮 2026-09-02](https://www.vgover.com/news/233433)
- **存储**：只有本地存储（见上表），没有云端存储。
- **网络**：**完全禁止**（fetch、XHR、WebSocket、SSE、WebRTC，以及加载外部图片和字体）。【官方】
- **AI/LLM**：有，但只能生成文本，而且在内测加白阶段。**AI 图像处理这类重计算做不了**（不能联网调外部模型，也不能跑 WASM 模型）。【官方】
- **支付**：**没有**（PaymentRequest 在移动端也不支持）。【官方】
- **分享**：有发笔记、带图评论、平台层面的分享（私信/群/站外）。不能复制到剪贴板。【官方 + 从业者】
- **媒体/相机**：有（见上表）。
- **定位**：网页的 `navigator.geolocation` **禁用**；但平台提供了 `getLocation`（9.49+，单次）。【官方】
- **关注/涨粉**：这是 10 月新增、对你最关键的一条。工具里可以拉起“关注作者”确认框，还能查到是否已关注，等于把“用完 → 关注”这一步做进了工具里。【官方】
- **跳转原生页**：官方 Skill 1.4.1（2026-08）里出现过一个 `openRedPage`，“type 必须在 Native 白名单里”，但**当前公开的能力清单没有列出它**。所以应该当作“不可用”，或者说“未公开”。【官方文件 + 推断】

### 2.3 和小红书小程序的区别

| 维度 | 小工具 | 小程序 |
| --- | --- | --- |
| 技术 | 纯 H5 zip，单个 index.html | XHSML + JS 框架，有专用开发者工具；Taro/uni-app 可以编译过去 |
| 主体 | 个人创作者账号 | 企业、个体户等；交易型需要专业号认证 |
| 服务端 | 无 | 有：登录（open_id）、手机号、地理位置、支付、客服、群聊等 |
| 收钱 | 不能 | 交易型可以（担保支付；目前只支持支付宝，微信支付安卓灰度中） |
| 审核 | 小工具审核（规范没有公开） | 主体认证、类目、备案（管局最长 20 个工作日）、发版审核 3–5 个工作日 |
| 曝光入口 | 笔记、评论、榜单 | 主页、店铺、POI、笔记、直播间、私信/微信分享 |

来源：【官方】[小程序介绍](https://miniapp.xiaohongshu.com/doc/DC137160)、[框架开发（Taro/uni-app）](https://miniapp.xiaohongshu.com/doc/DC598758)

## 3. 局限性

### 3.1 谁能发、要不要钱

- **准入**：多家媒体都说，全量后“粉丝数大于 1000、注册满 6 个月的实名认证账号”可以上传。【媒体】[电玩帮 2026-08-23](https://www.vgover.com/news/231762)、[巨游工坊 2026-08-24](https://juyougf.com/articles/20260824-ai-minigame-content-platform.html)、[源Sight/腾讯新闻 2026-09-22](https://news.qq.com/rain/a/20260922A095WP00)。也有报道说“内测期只有粉丝 ≥1000 的国内注册用户能发，而且每天限量”。【媒体】[什么值得买](https://post.smzdm.com/p/al3lvmv8/)
    - ⚠️ **我没找到“科技薯”公告的原文**，所以门槛是否还在、是否已经放宽，**需要你登录创作服务平台自己确认**。
- **主体**：没有看到任何关于企业或个体户的要求。个人账号就能发。【媒体】
- **费用**：没有看到任何收费的报道或文档。【推断：目前免费】
- **对比**：如果要做“小程序”，个人主体做不了交易型。从业者整理过一条路径：个体户执照 + 专业号认证（据称 600 元/年）+ 备案。【从业者】[夜雨聆风 2026-09-29](https://www.yeyulingfeng.com/a/1097410.html)（600 元/年这个数没有在官方页面上核实）

### 3.2 审核

- 流程是：上传 → 选版本号和权限（相册/摄像头/麦克风/本地存储）→ 扫码预览 → 提交审核 → 通过后变成“已发布”。之后可以下架、编辑、更新版本。【从业者】[woshipm](https://www.woshipm.com/ai/6432615.html)、[苏米客](https://xmsumi.com/detail/3827)
- 审核时长差别很大：内测期有人“几分钟就过了”【从业者，2026-07】；全量初期有人“挂上去一天了都没审核”【从业者，X，2026-08-25 15:17 UTC+8】；也有头部创作者抱怨“审核时间太长，没有好的测试手段，上线出问题要改又得等很久”，希望能回滚到旧版本、能小范围内测。【媒体采访】[游戏日报/网易 2026-09-03](https://www.163.com/dy/article/L5TU58MS052682V2.html)
- **小工具专门的审核规范或内容规范：没有找到公开文档。**【未知】按常理，社区规范、版权、未成年人保护、AI 生成内容这些规则都适用。【推断】

### 3.3 技术和体积限制（官方）

- zip 包**最大 10MB，建议 2MB 以内**；`index.html` 必须在 zip 根目录；只支持一个入口、单页应用。【官方】Skill `minitool-zip-builder` 1.4.1 的 `zip-artifact-spec.md`（下载地址：`https://fe-static.xhscdn.com/mini-tool/1.4.1/minitool-zip-builder.zip`）；10MB 这个数也得到了媒体佐证：[澎湃 2026-10-05](https://m.thepaper.cn/newsDetail_forward_34199244)
- 包里只能放 .html/.css/.js/图片/woff/json；**音频/视频**在 1.4.1 版规范里写的是“JS / CSS / 图片 / 音频等，平铺或分目录皆可”，CSP 也允许 `<audio>/<video>` 用包内媒体，所以音频可以打包（早期 1.2.0 版的文件类型表没列，是文档滞后）。实际播放仍建议真机实测。【官方】
- **脚本必须外置，而且是经典脚本**：不能内联 `script`，不能用 `onclick=`，不能 `type="module"`，不能 import/export。还禁用 eval、new Function、WASM、Worker、SharedArrayBuffer、iframe、表单跳转、文件下载、`target=_blank`、跳到其他小工具、长按菜单。【官方】
- 兼容性：Android 按出厂 Chrome/WebView 61 交付；**iOS 最低 18.4**。【官方】有用户反馈旧系统打不开，或者提示“当前地区不支持”。【媒体】[什么值得买](https://post.smzdm.com/p/al3lvmv8/)
- **存档不可靠**：官方要求“不要把浏览器自带存储当成可靠的持久化方案”；《开蚌直播间》出现过大量玩家存档消失。【官方 + 媒体】

### 3.4 数据

- **拿不到用户身份**，也就没法做账号体系、CRM、留存分析。
- 后台能看到“使用人数”等数据（榜单上有使用人数和 7 天活跃）。**开发者后台具体有哪些指标（打开率、留存、来源）没有公开文档**。【未知】
- 不能联网，所以**不能自己埋点上报**。只能看平台给的数据。【推断，依据官方禁网规则】

### 3.5 导流（站外引流）

- 小工具从技术上就打不开外链，也不能跳转站外。【官方】
- 小程序规范明确写了“小程序内不得含有站外导流内容（比如用二维码引流到微信、淘宝）”。【官方】[小程序介绍](https://miniapp.xiaohongshu.com/doc/DC137160)、[小程序管理规范](https://miniapp.xiaohongshu.com/doc/DC246380)
- 小组件的官方文档也提到，独立开发者的痛点是“App 跳出去到商店下载，折损高，笔记引流会被处罚”。【官方】[小组件介绍](https://miniapp.xiaohongshu.com/doc/DC026740)
- **【推断】**在小工具里放二维码、微信号、App 下载引导，大概率会被判违规。“小工具当免费版，App Store 卖完整版”这条路**不能在站内明着说**，只能靠作者主页、品牌词搜索这类软性方式。

### 3.6 其他风险

- **抄袭成本低**：生成门槛低，复制别人的玩法也很容易。【媒体】[巨游工坊](https://juyougf.com/articles/20260824-ai-minigame-content-platform.html)
- **IP 风险**：大量 4399 经典小游戏被复刻（比如“阿sue美甲店”）。【媒体】[源Sight](https://news.qq.com/rain/a/20260922A095WP00)。**【推断】**一旦版权方出手，这类工具随时可能被批量下架。做原创才更安全。
- **游戏版号**：小工具里大量是小游戏。平台和监管以后会不会要求资质，**目前没有公开说法**。【未知】

## 4. 技术栈

### 4.1 官方开发方式：“改写口令 + 官方 Skill”

- 上传页的“第一步”会给你一段口令。把它交给 AI 助手，助手按口令下载对应版本的 Skill，解压到工作区（Cursor/Claude Code 放 `.claude/`，Codex 放 `.codex/`），读 `SKILL.md`，然后校验、修复、打包，输出 zip。【官方 + 从业者】能力清单里也强调“不要沿用手工保存的旧口令”，因为口令会跟着版本更新。
- Skill 里有 4 份参考文档：`zip-artifact-spec.md`（包结构、模板、自检）、`device-capabilities.md`（哪些可用、哪些不行、怎么替代）、`jsbridge-api.md`（`window.xhs.miniTool.*`）、`cross-platform-h5.md`（触摸、安全区、PC 模拟器和真机的差异）。【官方文件】
- 我在 CDN 上能下到的版本有 1.2.0、1.3.0、1.3.1、1.4.0、1.4.1。线上口令现在指向哪个版本，或者是不是换了文件名，**我没法确认**（需要登录上传页才能看到）。能力清单里的 AI 和文件系统 API 比 1.4.1 新，说明还有更新的 Skill。【官方文件 + 推断】

### 4.2 框架怎么选（我的判断）

- **原生 HTML/CSS/JS 最省事。**体积小、没有构建坑，最适合测试、计算器、Canvas 小游戏。【推断】
- **React/Vue/Svelte 也能用，但要注意**：构建产物必须是**单个 HTML 入口 + 经典脚本**（不能有 ES module 或动态 import 拆包），要转译到 ES2017 / Chrome 61，不能依赖 eval，所有资源走相对路径。用 Vite 的话，大概要配 IIFE 输出、关掉代码分割、加 legacy 转译。**这点没有官方示例，需要实测。**【推断】
- **不能用的库**：依赖 WASM 的（ffmpeg.wasm、onnxruntime-web、各种抠图/OCR 模型、Draco/Basis），依赖 Worker 的（pdf.js 默认 worker、OffscreenCanvas），运行时用 `new Function` 的模板引擎或部分图表库。官方明确列了 WASM 加速库和抠图算法库不可用。【官方 + 推断】
- **Taro / uni-app**：官方文档写的是它们编译成“小红书小程序”（`@tarojs/plugin-platform-xhs`、`mp-xhs`），**跟小工具无关**。【官方】[框架开发](https://miniapp.xiaohongshu.com/doc/DC598758)
- **AI 或零代码生成**：小红书**没有内置生成器**。按虎嗅的说法，各平台里只有抖音把 Trae 接进了创作流程。【媒体】[虎嗅/扬帆出海 2026-08-19](https://www.huxiu.com/article/4884344.html)。创作者常用的组合是：ChatGPT 写 PRD → Codex 出 demo → 用官方口令打包，3–4 天就能上线。【媒体】[澎湃](https://m.thepaper.cn/newsDetail_forward_34199244)；元宝、Kimi K3（K399）、Cindy AI 这类工具也有人用。【媒体】
- **后端和云**：**没有。**唯一的“云能力”是平台 AI 文本生成。**你在 Vercel、Cloudflare 上的任何后端都调不到。**【官方】

### 4.3 发布流程

1. PC 打开[创作服务平台](https://creator.xiaohongshu.com/) → Builder Hub → 小工具 → 新建（名称、简介/Slogan、图标）
2. 复制改写口令 → 让 AI Agent 打包 → 上传 zip（部署失败一般是没按规范改）
3. 填版本号，选权限（相册/摄像头/麦克风/本地存储）
4. 手机扫码预览 → 提交审核 → 通过后是“已发布”
5. **单独发布不会被用户看到。必须在 App 发笔记时挂上它。**【从业者】
6. AI 能力：内测期要“在群里提交 uid”，平台再给对应 appId 加白名单。【官方】

**本地开发建议【推断】**：写一个 `window.xhs` 的 mock，在桌面 Chrome 里调 UI；再用 Android 8/Chrome 61 级别的设备（或者 BrowserStack）测兼容性；最后真机扫码预览。

## 6. 商业化

### 6.1 现状：小工具本身不能变现

- 不能联网、没有支付 API、不能跳外链。官方没有提供广告、内购、分成。【官方】
- 多家媒体确认：“小工具目前没有任何商业变现渠道，创作者收入只有大赛奖金和流量曝光”。【媒体】[什么值得买](https://post.smzdm.com/p/al3lvmv8/)、[游戏日报](https://www.163.com/dy/article/L5TU58MS052682V2.html)、[电玩帮](https://www.vgover.com/news/233433)
- X 上流传“小工具里可以接广告”，**跟“禁止任何网络请求”的官方规则矛盾，我判断不可信**（广告 SDK 要联网才能加载）。【从业者说法，存疑】
- 参照：抖音互动空间官方在群里回复“因为不需要创作者资质，暂时不支持变现，以后可能考虑 IAA”。【媒体】[电玩帮](https://www.vgover.com/news/231762)。**【推断】**小红书走同一条路（先开放、后考虑商业化）的可能性很大，但没有任何官方时间表。

### 6.2 现实可走的间接路径

| 路径 | 怎么做 | 门槛和风险 | 来源 |
| --- | --- | --- | --- |
| 涨粉 → 蒲公英商单 | 工具带来粉丝和账号权重，再接品牌合作 | 蒲公英要求一定粉丝量和专业号等（以蒲公英官方为准）；商单内容必须报备 | 【从业者 + 推断】 |
| 品牌定制小工具 | 给品牌或商家做测试、计算器、互动游戏，挂在品牌或博主的笔记上 | 目前没有官方的“品牌小工具”产品，属于线下接单 | 【推断】 |
| 带货、知识付费、打赏 | 账号挂商品或卖课；笔记“送礼物” | 和工具本身关系不大 | 【从业者】[夜雨聆风](https://www.yeyulingfeng.com/a/1097410.html) |
| 升级到交易型小程序 | 个体户或企业 + 专业号 → 开发小程序 → 担保支付 | 目前主要是支付宝（微信支付安卓灰度）；技术服务费通用类目 0.6%、T+7；软件工具、AI 问答、AI 绘画等类目在费率表里 | 【官方】[技术服务费规范](https://miniapp.xiaohongshu.com/doc/DC134211)、[小程序介绍](https://miniapp.xiaohongshu.com/doc/DC137160) |
| 跨平台承接 | 在小红书爆了以后，把联网 + 内购版放到别的平台 | 案例：《阿珠开蚌直播间》入驻网易星匣，上线了可联网版本，靠内购道具实现盈利（两边合计至少 220 万人次）。站内不能明着导流 | 【媒体】[澎湃](https://m.thepaper.cn/newsDetail_forward_34199244) |
| 比赛奖金 | 每个赛道金银铜分别 2 万/1 万/7000 元，另有入围奖和人气奖（第一期） | 一次性收入 | 【媒体】 |

**个人和公司结算有什么不同**：小工具没有结算，所以无所谓。小程序方面，个人主体不能开交易型，个体户主体名称后面要加“（个体工商户）”。【从业者转述官方】iOS 上的虚拟商品、订阅能不能在小红书小程序里卖，**这次没核实到官方条款**。【未知】

### 6.3 算一笔账（【推断】）

- 平台 AI 是免费的：一个 AI 文案工具每次调用成本为 0。**对独立开发者来说，这是相比自建 App 最实在的好处**（App 里每个用户每天都要花 token 钱）。
- 但“使用量 → 收入”的转化只能靠账号。所以小工具的 ROI，其实就是“账号的粉丝和影响力能带来多少钱”。

## 8. 适合你（独立 AI 产品人 + App Factory）的机会点

选题原则（【推断】）：①小红书上需求密集（有大量“求工具”帖子）；②结果“值得晒”，能自然走 postNote 或评论；③不需要联网，文本 AI 或者纯本地计算就能做到 80 分；④能沉淀成账号人设（比如“AI 小工具工厂”）。

1. **AI 小红书文案/标题诊断器**：用“点点”模型（小红书调性），输入草稿，输出标题打分、改写和话题建议，一键 postNote 带进发布页。完全命中站内创作者的需求，而且 AI 是免费的。风险：每个用户每天 100 次的配额；平台会不会限制“营销类 AI 工具”。
2. **测试 + AI 个性化解读 + 结果卡**：MBTI、恋爱、职业、“你在 XX 剧里能活几集”这类。本地题库 + AI 解读 + Canvas 生成分享卡 + 评论区 PK（快照恢复状态）。媒体统计中测试/恋爱类是流量最大的一档（【媒体】什么值得买）。
3. **本地图片/实况工具**：拼豆图纸、九宫格切图、水印和拼图、手帐模板、**实况照片生成**（postNote 支持 live_photo_sources，这是小红书独有的格式）。做不了抠图模型（不能跑 WASM），但可以做纯 Canvas 算法。
4. **垂类计算器、规划器**：租房成本、退休年龄、生育账单、旅行预算和行程、健身饮食热量（你的 Health & Fitness 方向）。媒体报道的热门工具里就有“生育账单”“新退休年龄”这一类（【媒体】新榜/游戏日报）。
5. **AI 角色/陪伴轻聊天**：做有人设的 IP 角色，对话历史存在本地。注意 40 条、12000 字符的上限和不支持流式。
6. **App Factory 的“试吃版”**：把你计划做的 iOS App，先拆出一个核心功能做成小工具，用笔记测需求。数据好的再做原生 App。**站内不要导流**，用户想要完整版自然会搜品牌名或者看你的主页。
7. **小游戏、互动叙事**：竞争最激烈（Top10 里 7 个是休闲游戏），但最容易爆。建议只在有原创 IP 或强梗的时候才做。
8. **给品牌、博主做定制小工具（B2B 服务）**：用你的产品和 AI 开发效率接单，属于账号以外的现金流。

## 10. 下一步验证计划（建议 3 周，【推断】）

**第 0 周（1–2 天）：资格和环境**

- [ ]  登录[创作服务平台](https://creator.xiaohongshu.com/)，确认 Builder Hub → 小工具入口是否可用；如果卡在粉丝门槛，就用现有账号先发 build-in-public 内容攒粉，或者用符合条件的账号。
- [ ]  复制最新口令，拿到最新 Skill，读完 `SKILL.md`，在仓库里建一个小工具模板（Vite IIFE 单文件或原生，加 `window.xhs` mock）。
- [ ]  申请 AI 白名单（按文档“在群里提交 uid”）。

**第 1 周：做 3 个工具，每个不超过 1 天**

- A：AI 文案/标题诊断（测 AI 和 postNote 闭环）
- B：Canvas 结果卡类测试，或者实况照片工具（测评论区 PK 裂变）
- C：一个垂类计算器（测“需求帖 → 工具”的搜索流量）
- 记录：审核用了多久、真机兼容问题、包体积。

**第 2–3 周：内容分发实验**

- 每个工具发 3–5 篇不同角度的笔记（痛点型、结果展示型、教程型、合集型）。
- 每天记一次：笔记曝光和阅读、工具使用人数、用户自发 postNote 和评论晒图的数量、涨粉数、私信或商务咨询。
- 实测第 9 节里的第 3、4、5、8 条。

**决策门槛（建议值，按你的目标调）**

- ✅ **继续加码**：至少 1 个工具 2 周内使用人数超过 1 万，或者带来超过 500 新粉；而且看得到自发 postNote 和评论晒图。
- ⚠️ **保持低投入**：使用人数在 1000 到 1 万之间。把小工具当成 iOS App 的需求测试工具，每月做 1–2 个。
- ❌ **暂停**：5 篇笔记以后使用人数还不到 1000，或者一直卡在审核和门槛上。

**同时进行**：iOS 主线继续。如果某个工具验证成功，再看要不要用个体户主体做交易型小红书小程序，或者原生 App 来承接付费。
