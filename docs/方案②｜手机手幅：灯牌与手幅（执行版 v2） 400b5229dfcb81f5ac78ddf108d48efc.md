# 方案②｜手机手幅：灯牌与手幅（合并执行版）

**产品定位**：把手机变成随手可用的加油牌。灯牌突出文字展示，手幅突出设计感、近距离展示与观赛合照。面向王楚钦、孙颖莎与莎头球迷；对外统一称球迷，不使用娱乐圈式产品叫法。

本版在原方案结构上合并修改，保留历史调研来源、场景、功能清单、配色、场馆友好交互、打印、开发步骤、指标与赛事推广节奏；补充手机适配、页面交互及参考图。旧74条口号库停用，其他有效需求不因改版被整体删去。

## 2. 用户与场景

### 2.1 赛前攻略

用户从“能带什么、能不能带手幅、安检严不严”的笔记进入。笔记分清规则事实与个人体验，挂载工具；工具提供提前选款、改字、保存，不保证现场获准展示。

### 2.2 赛前准备

面向忘做、来不及做、担心实体物料被拦的球迷。选择灯牌或手幅 → 选款 → 套用已确认文字或自填 → 保存到「我的牌」。不用先学习编辑器。

### 2.3 现场

再次进入优先看「我的牌」，点开直接展示；不要求重新挑款。灯牌用于简洁口号展示，手幅用于近距离展示与合照。展示页一键收起，不允许界面误触后丢失设计。

### 2.4 赛后与居家

观赛体验笔记可附手幅图、合照或设计截图，并手动挂载用过的小工具。居家看直播为补充场景，不作为首版主要增长假设。

### 2.5 互动传播

作者发使用笔记并挂工具 → 球迷制作自己的牌 → 评论区晒图或发观赛笔记 → 其他人从挂件进入制作。允许挂载他人用过的工具这一点来自已有创作者体验，发布时需在当前账号实测。

工具提供「晒到评论」「发笔记」两种出口；发布草稿并不等于最终发布或审核通过。`postNote` 公开参数没有挂载工具字段，不能据此保证自动挂载，也不能断言平台永远不会附带；首版实测，并提示用户检查发布页挂件。

### 3.2 页面流程

#### 首页：选款

顶部标题「手机手幅」，说明「选一句话，做一块自己的加油牌」。两个等权入口：「灯牌」「手幅」。下方是模板实图，不用纯文字风格名称代替预览。

固定「我的牌」入口；有本地存档时展示最近使用款，点开进入原设计。首次展示前提示「是否允许举牌，以当场规定为准；回合中请收起，勿遮挡他人」。不每次启动重复弹窗。

#### 编辑页

上半屏展示与最终横屏构图一致的实时预览；下半屏按「文字、款式、颜色、图形」排列。底部固定「展示」「保存图片」。

- 文字：已确认口号标签、自定义输入、单行或双行。支持中文、英文、数字、emoji，按实际渲染宽度适配，不按字符数机械截断。
- 超长处理：先提示“文字较长，建议换行或精简”；灯牌可主动选择滚动；手幅不得把字缩到不可读或静默删字。
- 款式：切换同类模板保留文字与兼容颜色；切换灯牌/手幅保留文字，但恢复该类的合理排版。
- 颜色：提供每款精调色组，也允许自定义。显示色块与预览，不给特定球迷群体擅自指定统一颜色。
- 图形：有限位置的原创贴纸和边框，点击切换、可关闭；首版不做任意拖拽的复杂画布编辑器。
- 保存：本地保存最近5个设计。重复修改同一设计覆盖原记录；另存为新牌才新增。失败时明确提示“未保存，请先存图”，不能显示保存成功。

#### 展示页

「进入展示」隐藏工具内编辑控件，优先提示横持手机；不承诺隐藏平台导航栏或调用系统全屏。版式随容器实际尺寸适配，避开顶部原生按钮与刘海。

- 灯牌：默认静态短口号，文字占主视觉；滚动为可选，提供原版5档速度、方向、循环设置和停止按钮。
- 手幅：静态彩色构图，保留设计字和一个主图形，不播放装饰动效。
- 轻点出现操作层，明显按钮「收起展示」立即退出到编辑页；不能只靠用户猜双击/长按手势。恢复编辑保留输入。
- 手动设置提醒：手机亮度和自动锁屏由用户在系统设置中处理；页面不能保证常亮或自动调系统亮度。
- 不识别现场赛况，不自动判断发球、回合或暂停；不把屏幕蒙层描述为系统亮度调整。

#### 保存与分享页

- 「保存图片」：导出当前牌的横版平面图，默认1920×1080，图上不叠加编辑按钮。该尺寸是图片规格，不是手机固定显示比例。
- 「晒到评论」：将当前设计嵌入1080×1080的晒图卡，主牌保持自身比例、完整显示，不拉伸成方形；通过平台评论草稿能力带入。
- 「发笔记」：提供1080×1440展示卡，包含当前牌和简短工具署名；不是伪造现场返图，不加虚构座位、赛事或日期。
- 分享卡有工具署名；现场展示图默认不放宣传水印，保持文字面积。
- 分享失败保留设计，可重试或改存相册。存相册被拒绝时说明权限问题，不提供“长按保存”这种容器已禁用的假降级。
- 保留原版A4打印导出：横版3508×2480像素；后续A3横版4961×3508像素。按该画布重新排版，不把手机截图拉伸当作打印稿；实体物料是否可带入另按规则判断。不做强制关注解锁。

## 5. 视觉设计规范

### 5.1 灯牌：口号清楚优先

- 重点是字形、字重、描边和适度发光，不局限黑白。短句用静态大字，长句可滚动。
- 控制发光范围，保持字芯清晰；不能把轻细霓虹线条直接拿来做所有中文大字。
- 允许少量星形、爱心、薯条等原创符号；字面积优先，图形不能挤成徽章上的小字。
- 异形指屏幕内的视觉轮廓，手机屏幕本身仍是矩形；异形边框不能成为大块无用留白。
- 不承诺20–30米可读。样稿必须真机横持，在近处与约3米处分别检验；合格距离以实测记录为准，不拿WCAG文本对比度替代现场识读测试。

### 5.2 手机手幅：可展示、想晒

- 为手机横屏重新构图，不等比缩小宽长实体手幅。文字为一句主文案，最多两行；配一个主图形，少量辅助贴纸。
- 保留参考的配色、设计字、图形语法，删除多照片拼贴、长段副文案、小号日期、密集边角装饰。
- 彩色可用于背景、字面、描边及图形，需成套精调，不把“改前景色”当作完整设计。
- 可用粗圆描边字、运动字、贴纸拼贴、低密度渐变等；不得将“年轻女性”直接等同于全粉色、全爱心。
- 首版不使用未经授权的人像、摄影作品、Q版人物、赛事logo和队徽。参考图中的人物只用于理解信息层级，不带入成品。字体与装饰素材留存授权。

### 5.3 首版模板交付

首版6款，两类各3款。编号固定用于开发配置与验收；色组为建议方向，不是球迷群体的官方颜色。

## 6. 场馆友好模式（默认开）

- 保留原版观赛提示：回合中收起、别挡后排、以当场须知为准；不把局间/颁奖自动认定可举。

## 7. MVP范围与技术要求

- 纯离线HTML/CSS/JS，Canvas 2D渲染；脚本外置，兼容Chrome 61 / ES2017，按上传页当前官方Skill校验。所有字体、贴纸、背景打包在内，不接图片CDN、云字体或外部生成接口。
- zip上限以当前上传页/Skill为准，既有规范为10MB、建议2MB；本项目先按2MB目标优化，不因参考图多就全部塞进安装包。参考集不打包进产品。
- 平台能力：`saveImageToPhotosAlbum`、`writeTempFile`、`postNote`；评论使用`interactionOpenApi`（9.49+）；本地缓存使用Storage（9.46+）。均需检查方法、版本、权限与错误结果。
- 评论图片使用容器可访问的本地文件句柄；不能假定`writeTempFile`返回值一定符合评论侧契约，真机验证，不兼容则使用文件系统能力保存后再传。
- 使用容器尺寸与安全区布局；禁止调用`requestFullscreen`或依赖锁屏方向API。CSS旋转只作真机验证后的兜底，不能牺牲按钮命中与触摸坐标。
- 不接入AI，不上传自定义文字，不承诺本地数据永久有效；存图可作为应急展示方式。
- MVP含：A4打印导出、简版返图卡、6款、两类、已确认口号与自填、配色、横屏展示、静态/灯牌滚动、本地5个设计、存图、评论/笔记草稿。
- 不含：A3打印、多人同步、全场联动、自动赛况、声音、闪烁、AI创作、任意画布编辑、拍照合成、排行榜。
